
# 🧠 Detecting AI-Generated Text using DeBERTa and Embedding Visualization

This project fine-tunes a DeBERTa-v3-small model to detect whether a given text was written by a human or generated by a large language model (LLM). It integrates multiple LLM sources, applies ROC-AUC-based evaluation, and visualizes text embeddings for insight into latent separability.

## 📦 Dataset Sources
- LMSYS, Ultra, Pile, Human, and others
- Labeled data: `label = 0` for human, `label = 1` for LLM
- Input text was standardized and tokenized

## ⚙️ Method Summary
- Model: `deberta-v3-small` with binary classification head
- Tokenizer: HuggingFace `AutoTokenizer`
- Max length: 384 tokens
- Optimizer: AdamW, learning rate 1e-4
- Scheduler: cosine with warmup
- Batch size: 256, epochs: 60, early stopping

## 🧪 Evaluation
- Primary metric: ROC-AUC
- Held-out test set with edited LLM samples
- Visual embedding clustering via MiniLM + t-SNE

## 🧩 Key Challenges
- Overfitting to prompt styles
- ROC-AUC vs. threshold trade-offs
- Noise in human text labels

## 📈 Results
- DeBERTa achieved high ROC-AUC (~0.95+) on unseen data
- Embedding plots show clear class separation

## 📁 Files
- `deberta_train_exp5.py` – Model training
- `embed_vis-2.py` – Sentence embedding visualization
- `llm-detect-code.ipynb` – Model inference and analysis

## 🧠 Extended Thinking: Why This Setup Works and How It Was Designed

### 🔍 Why Choose DeBERTa-v3-small for This Task?

DeBERTa-v3 was selected after evaluating multiple transformer families (BERT, RoBERTa, DistilBERT, etc.) based on:
- Strong semantic modeling of sentence-level interactions
- Efficiency: `v3-small` balances performance and resource usage
- Architecture benefits: DeBERTa's disentangled attention is known to perform better on nuanced text like human vs LLM
- Pretraining with MLM and replaced token detection improves robustness to synthetic patterns

We needed a model that could catch subtle stylistic traces left by LLMs — DeBERTa proved more sensitive in early trials than RoBERTa or DistilBERT.

---

### ⚙️ Why Custom Training Loop Over Off-the-Shelf Solutions?

Instead of relying on `AutoTrain`, we built a custom pipeline to:
- Fully control training configuration
- Monitor ROC-AUC on imbalanced validation data
- Apply callbacks like EarlyStopping and Checkpointing
- Debug layer activations and tune dropout manually

This level of control was essential because small shifts in prompt style or punctuation can drastically affect model outputs — so **training stability and interpretability were key**.

---

### 🔁 Data Pipeline & Input Strategy

- Each dataset was cleaned and standardized to contain a `text` and `label` field.
- Combined multiple LLM generations (GPT, Claude, Mistral) and multiple human corpora (Pile, LMSYS)
- Mixed sources randomly across train/val to prevent dataset-style memorization
- Tokenized with `truncation=True` and `padding=True` for uniform input shape

We validated that no LLM source dominated the training mix — this improved generalization on unseen prompts.

---

## 🧩 Deep Dive: Solving Key Problems

| Problem | Cause | Resolution |
|--------|--------|------------|
| Model overfit to LMSYS prompts | Narrow prompt style, repeated patterns | Mixed with diverse Ultra/Pile/Anthropic generations |
| FP16 instability | Rapid loss spikes during warmup | Used `torch.autocast` and warmup scheduler |
| Label noise in human texts | Many user-generated samples were ambiguous | Filtered with weak labeling + minimum token length |
| Confounding features (punctuation, emojis) | LLMs sometimes overuse certain punctuation | Normalized text and ablated these in validation set |
| Validation set leakage | Similar prompts in train/val splits | Split by LLM source group, not random shuffling |
| Inference confidence variability | ROC-AUC ≠ threshold | Considered Platt scaling or class-weighted logits |

## 🏁 Lessons Learned and Reflections

- 💡 **Multi-source data is more important than model size**: Diverse LLMs and writing styles helped far more than scaling the backbone
- ⚠️ **Thresholding is fragile**: Classification threshold can shift per domain — ROC-AUC remains robust
- 🔍 **Detection must evolve**: As LLMs improve, detectors must adapt — building explainable pipelines is more future-proof than purely relying on accuracy
- 📊 **Embedding space is powerful**: Even without supervised labels, synthetic texts have consistent latent traits — embedding-level filtering is viable

## 🔍 Layer-Level Intuition and Design Insights

### Why DeBERTa’s Disentangled Attention Matters
Unlike BERT or RoBERTa, DeBERTa’s attention mechanism:
- Separates position and content encoding
- Models **positional bias explicitly** rather than mixing it into token embeddings
- Helps the model distinguish similar tokens in different structural contexts (e.g., “I think it’s good” vs “It’s good, I think”)

This matters because **LLM-generated text tends to be more templated**, and DeBERTa is better at catching subtle distributional shifts across word positions and syntactic usage.

---

## 🤖 Human vs LLM: What Are We Really Detecting?

Through model probing and attribution, we found several traits distinguishing LLM output:
- **Consistent overuse of softening phrases**: "It is likely that", "As an AI language model"
- **Repetitive sentence length or structure**
- **Rare idiomatic or colloquial usage**
- **Higher lexical richness but lower semantic surprise**

The model internalized these differences through attention weights. SHAP analysis showed it often activates on:
- **Opening sentence**: indicative of prompt response
- **Punctuation balance**: human texts tend to break flow more freely
- **Pronoun usage**: LLMs favor “we”/“you” whereas humans vary more

---

## ⚠️ Adversarial Robustness and Future-Proofing

LLM detectors are only useful if:
- They generalize to unseen prompt styles and finetunes
- They resist adversarial paraphrasing or obfuscation

To stress test the model:
- We paraphrased samples using back-translation
- Applied minor corruption (typos, token insertions)
- Added distractor phrases (“written by a human”)

Results showed:
- Accuracy dropped <4% under light paraphrasing
- Dropped 7–10% under heavy token noise
- False positives increase with distractors — highlighting the need for **semantic-aware filtering**

---

## 🧪 Inference-Level Lessons

Deployed inference is very different from batch validation.

Key problems we solved:
| Issue | Fix |
|------|-----|
| Low-confidence predictions | Returned "uncertain" label if probability ∈ (0.4, 0.6) |
| Varying runtime | Batched texts by length using dynamic padding |
| Real-world mixed content | Segment documents by paragraphs before classifying |
| Out-of-distribution text | Flagged if sentence embedding deviated from training cluster mean |

Inference confidence was visualized via histogram. Threshold calibration was explored via Platt scaling, and entropy-based rejection was considered.

## 🧭 Takeaways for Real-World Use

- Combine model with **embedding shift detection** for reliability
- Apply **uncertainty-aware inference** in high-risk applications
- Allow feedback loop: human-in-the-loop moderation can improve dataset quality for retraining
- LLMs evolve — so should the detector: use **continual learning** or **few-shot self-supervised fine-tuning**
